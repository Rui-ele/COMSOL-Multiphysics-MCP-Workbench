# COMSOL 方案汇报材料（第四节）

前文见[项目目的](project-purpose.md)和[硬约束与方案比较](constraints-and-options.md)。本页描述目标架构与建设方式，不代表各项能力已经实现。

## 4. 目标架构与任务编排

### 4.1 目标架构

推荐架构的核心是把“分析”和“执行”解耦，同时在两者之间建立稳定的任务协议：

**专家 → GPT / 外部强模型 → 结构化任务 → 本地 Agentic Harness → COMSOL MCP → COMSOL**

执行完成后，再沿相反方向返回：

**COMSOL → COMSOL MCP → 结构化结果 → GPT → 专家**

其中：

- **专家**负责定义问题、技术判断和最终确认；
- **GPT / 外部强模型**负责辅助分析，并把专家意图整理成适合本地系统执行的任务；
- **本地 Agentic Harness**负责按照任务协议调用工具并完成多步执行；
- **COMSOL MCP**负责读取模型、执行修改和回读实际状态；
- **任务状态与调度能力**负责计算任务的状态保存、查询和已确认任务的排队接续；具体承载方式按 4.4 节选择。

因此，GPT 在系统中不仅是“聊天助手”，还承担一层**任务编译**作用：

**把专家的自然语言意图转换成本地系统更容易稳定理解和执行的任务；再把本地系统返回的结构化事实转换成专家容易判断的信息。**

---

### 4.2 双向任务协议

为了降低自然语言在系统内部传递时的歧义，专家与 GPT 之间可以继续使用自然语言，但 **GPT 与本地执行系统之间应尽量采用结构化协议**。

协议需要解决两个方向的问题。

#### **GPT → 本地执行系统**

GPT 将专家已经明确的意图整理成结构化任务。

这里不要求完全取消自然语言，而是采用：

**固定字段 + 必要的自然语言描述**

例如固定表达：

**任务目标、操作对象、执行边界、预期结果**

复杂的技术要求仍可以保留为自然语言内容。

这样可以避免本地 Agent 每次重新猜测一段自由文本到底想做什么。

#### **本地执行系统 → GPT**

执行结果也应按照稳定结构返回，而不是只返回运行日志或自由文本。

核心是让 GPT 能够快速区分：

**实际读取到的状态、执行过的操作、核验结果以及异常情况。**

因此，这套协议的作用不是单纯定义 API 字段，而是建立一个稳定的：

**专家意图 → 可执行任务 → 实际执行事实 → 专家判断**

的信息闭环。

具体字段不需要一次性全部确定，可以随着 PoC 逐步稳定。

### 4.3 Agentic Harness 的建设范围

本地 Agentic Harness 不需要从零开发。

Codex、Claude Code、OpenCode 等工具本身已经提供 Agent 循环、工具调用、上下文管理和基础任务执行机制。这部分属于工具自身的 Harness，通常只能选择和使用，不能大幅修改其内部调度逻辑。

真正需要建设的是**项目级执行环境**，主要包括：

**规则文件 + Skills + MCP 工具**

其中：

- `AGENTS.md` 等规则文件规定系统边界、执行原则和核验要求；
- Skills 固化已经成熟的高频任务流程；
- COMSOL MCP 提供 Agent 实际可以调用的 COMSOL 能力。

因此，建设重点不是重新设计一个 Agent 框架，而是：

**定义好任务协议，并让现成 Harness 按正确规则调用正确工具。**

---

### 4.4 任务状态与调度

计算任务需要与用户是否持续在线解耦。

对于已经启动的计算，即使用户关闭员工助手或手机断开连接，COMSOL 计算仍应继续运行；系统需要能够保存并查询任务状态，使用户重新连接后可以继续查看进度和结果。

如果存在多个已经由专家确认的计算任务，则进一步需要支持：

**任务排队 → 当前任务完成 → 启动下一项任务**

因此，这部分可以分成两个层次逐步建设：

**任务状态持久化与查询 → 多任务排队和自动接续**

员工助手主要作为任务提交、状态查询和结果查看的入口；具体如何保持任务运行、记录状态和实现接续，则根据现有员工助手、Agent 工具和 COMSOL 运行机制选择最简单的实现方式。

---

### 4.5 建设方式

系统不需要先把所有接口、Agent 和 Skills 全部设计完成，再开始测试。

更适合采用逐步扩展的方式：

**选择一个真实 PoC → 定义所需任务协议 → 配置规则 / Skill → 补齐 MCP 能力 → 实际运行 → 根据结果修正**

先跑通最小闭环：

**获取上下文 → 生成结构化任务 → 本地执行 → 结构化返回 → GPT / 专家核验**

随后再逐步增加新的任务类型和计算调度能力。

因此，接口字段、规则文件和 Skills 都是在真实任务中逐步沉淀出来，而不是在项目开始时一次性完整设计。
