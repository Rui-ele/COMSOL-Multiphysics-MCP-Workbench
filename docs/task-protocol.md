# 任务与报告约定

GPT 与用户讨论技术方案，确定本轮步骤和判据；员工助手中的千问 Agent 将计划组织成连续工具调用；MCP 完成每次具体操作并返回事实；COMSOL 维护模型状态并完成计算。用户在 GPT 和本地 Agent 之间整段转交任务与报告。

## 1. 本次任务

| 项目 | 写清什么 |
| --- | --- |
| 背景与目的 | 整体目标、本轮相关事实 |
| 本次任务 | 要取得的信息或完成的操作、范围 |
| 对象与步骤 | 实际标识或查找条件、调用与参数、操作顺序、依赖和条件分支 |
| 完成判据 | 读取什么、按什么条件确认完成 |
| 返回要求 | 需要完整保留的事实、列表、错误及待判断事项 |

对象可在同一任务内按条件定位，得到唯一匹配后继续操作。属性含义、目标值或技术方法需要判断时，GPT 先安排补采，再与用户明确方案。转交明确任务即授权本地执行。

### 任务模板

```text
背景与目的：<整体目标、本轮相关事实>
本次任务：<要取得的信息或完成的操作及范围>
对象：<模型和节点的标识，或明确查找条件>
步骤：
1. <读取或操作；具体调用、参数和值>
2. <前一步满足什么条件后，执行什么；明确依赖或分支>
完成判据：<本轮应取得的事实或应满足的条件>
返回要求：<完整值、列表、错误及待判断事项>
```

## 2. 步骤如何衔接

本地 Agent 负责连接、定位、调用顺序，以及根据计划与工具返回决定继续或停止。一次修改内部的前置条件检查、修改前取证、操作和回读核验，由 `comsol_api_write` 完成。

例如“修改设置 → 构建几何 → 生成网格 → 求解 → 读取结果”，是五个由 Agent 衔接的步骤。GPT 给出各步的具体方法和判据。异常处理与整轮报告规则集中在 [AGENTS.md](../AGENTS.md)。

## 3. 本次回报

工具返回单次调用的完整事实，本地 Agent 按任务顺序汇总成一份可复制报告。

```text
本次任务：<对应的任务目的>

简短摘要
- 已完成与验证：<完成项及依据>
- 未完成与当前状态：<受影响步骤和已知现值>
- 需要 GPT 判断：<具体问题、候选及区别，或本轮已完成>

完整事实
1. <实际对象、调用、参数、前置检查与取证>
2. <实际动作、回读、判据和验证结果>
3. <错误原文、来源、缺失信息和未执行步骤>
4. <后台任务的运行标识与实际状态；文件操作的实际路径>
```

事实保留模型版本与来源，方便 GPT 查阅对应资料。较长工具报告取齐分页后再汇总。GPT 根据整轮报告判断本次任务的完成情况，以及整体工程问题是否需要下一轮工作。

## 4. 一次完整往返

以下为假设例子：模型 `Model1` 的组件 `comp1` 中，物理场 `ht` 的边界条件 `hf1` 用于冷却面。

| 环节 | 任务或回报 |
| --- | --- |
| GPT 安排读取 | 读取该条件的实体选择与维度，返回实际列表和来源。 |
| 本地 Agent 回报 | 假设读取到维度 2、实体列表 `[5]`，附实际调用和返回值。 |
| GPT 与用户讨论 | 对照设计，明确本次应选边界 5 和 6。 |
| GPT 安排修改 | 对 `component("comp1") → physics("ht") → feature("hf1") → selection()` 调用 `set`，`args=[{"type":"int[]","value":[5,6]}]`。前置条件为 `entities()` 与 `[5]` 作 `same_items` 比较；写后验证与 `[5,6]` 作相同比较。 |
| 本地 Agent 调用 MCP | MCP 读取前置条件、执行一次 `set`、回读 `entities()` 并比较。Agent 用返回结果判断本步是否完成，汇总本轮报告。 |
| GPT 决定下一步 | 根据实际回读与整体目标，安排求解和结果检查，或总结当前结果。 |

如果任务最初只给出模型或节点的查找条件，本地 Agent 先完成定位，再执行同一任务中的上述步骤。

## 5. 工具报告与续页

具体工具签名、支持的方法和参数类型，以运行中的 MCP 工具定义为准。工具选择与执行方法见 [信息采集 Skill](../.agents/skills/comsol-diagnostics/SKILL.md) 和 [计划执行 Skill](../.agents/skills/comsol-model-edit/SKILL.md)。

### 公共报告字段

| 字段 | 内容 |
| --- | --- |
| `report_version` | 报告结构版本，当前为整数 `3` |
| `report_kind` | 本次调用的工具名 |
| `model_reference` / `model_tag` | 请求中的模型标识 / 已定位的实际 tag；未涉及或尚未定位时为 null |
| `request` | 本次调用参数对象 |
| `success` / `status` | 本次操作的成功标记与具体状态 |
| `summary` | 简短摘要文本 |
| `errors` | 调用级错误列表；分项读取的错误保留在对应事实中 |
| `started_at` / `finished_at` | 报告记录的开始与完成时间 |
| `runtime` | MCP 部署版本与源码信息 |
| `report_markdown` / `report_delivery` | 可复制报告及分页信息 |

事实内容随操作保留：采集报告有 `findings`、覆盖范围和缺失项；通用写入有 `preconditions`、`before`、`after`、`verification`；后台求解有 `run_id` 和运行状态。

写入报告中，`write_attempted` 表示已尝试操作，`write_returned` 表示调用正常返回，`verified` 表示回读符合任务判据。启动求解成功表示已经受理，完成情况通过同一 `run_id` 继续查询。

### 报告续页

较长报告先返回摘要字段和首段文本，完整请求与事实保留在分页报告中。`report_delivery` 包含 `report_id`、`next_offset`、`total_chars`、`complete` 和校验值。

按返回的 `next_offset` 调用 `diagnostic_report_page`，依次拼接各页 `report_markdown`，直到 `complete` 为真，再执行下一项。分页读取同一份冻结报告。

服务缓存最近使用的 16 份报告，重启后过期。续页失败时保留执行结果、已取得内容和缺页范围；需要新的当前状态时另行读取。

## 公司电脑人工验收

在安装 COMSOL 且有可用 License 的公司电脑上进行：

1. 在员工助手中配置 MCP、执行规则与 Skills，连接多客户端 Server，打开验收模型或副本。
2. 将问题交给 GPT，转交一份读取任务；确认本地可按查找条件定位对象并在同轮继续。
3. 读取较长属性或实体列表，确认各页能拼接为完整事实。
4. 取得一份创建节点及修改设置的任务，核对前置条件、取证、写后验证的独立作用。
5. 执行任务中的构建或求解，按运行标识查询真实状态，再继续已安排的结果检查。
6. 检查条件不符、对象歧义或调用失败的回报是否保留已完成项、当前事实和未执行步骤。
7. 将完整报告转回 GPT，由 GPT 判断本轮完成情况及整体目标的下一步。
